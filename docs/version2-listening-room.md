# Version 2 共创聆听室

## 目标

第三页是 Version 2 的主要共创场景。用户面对的是所选音乐家与中央水晶，主持智能体不显示人物，只通过顶部的一句舞台字幕控制节奏。

## 页面结构

- 中央水晶继续承担音乐播放入口和舞台视觉中心。
- 1-4 位音乐家使用按人数定义的固定席位，不进入水晶按钮的边界。
- 四段完整评论同时显示时采用上下两行，气泡之间保留间距。
- 用户回合时，听感入口显示“轮到你了”，但不增加新的弹窗或说明卡片。
- `VisualBrief` 只显示当前最前面的两条有效线索，并保留字段状态、色彩样本和来源提示。
- 展开播放器时暂时隐藏视觉线索，将播放器放入水晶正上方的中央通道。

## 布局约束

舞台区域使用 `overflow: clip`，防止按钮获得焦点时浏览器把舞台当作滚动容器。播放器展开、评论流式增长和用户输入都不能改变水晶、人物或 CTA 的坐标。

四人布局中：

- 外侧人物位于舞台下排，气泡位于下排。
- 内侧人物向左右展开并位于上排，气泡位于上排。
- 中央通道只留给视觉线索、播放器和水晶。

## 对抗审查

在 1280x720 桌面视口中以真实模型会话验证：

- 分别进入 1、2、3、4 位音乐家的聆听室。
- 完成两轮对话，使四段长评论同时出现。
- 检查所有气泡之间以及气泡与字幕、视觉线索、水晶、输入入口和 CTA 的边界交集。
- 展开播放器，检查播放器与四段评论、字幕、水晶、输入入口和 CTA 的边界交集。
- 检查舞台容器在播放器展开后的 `scrollTop` 和内容坐标。

最终边界检查无交集；播放器展开后舞台 `scrollTop` 保持为 `0`，主内容坐标保持不变。
