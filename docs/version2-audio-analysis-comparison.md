# Version 2 音频分析对比报告

## 1. 评测问题

`V2-03` 回答的不是“新工具字段是否更多”，而是三个更具体的问题：

1. 新方案是否比 Meyda 更完整地保留音乐证据？
2. 新增语义标签是否准确到可以被音乐家智能体当作事实？
3. 新方案的延迟是否适合后续公开体验？

对比使用同一批 8 首、每首 45 秒的预置音频。Meyda 通过生产代码中的 `analyzeDecodedAudio` 运行；新方案通过同一个常驻 `MusicAnalyzer` 依次运行 `librosa + CLAP`。

人工参考标签来自已知曲目、乐器、catalog metadata 和内部聆听导向审查。它们只是一份工程参考，不是论文级 ground truth。完整结构化结果见 [version2-audio-analysis-comparison.json](./evaluations/version2-audio-analysis-comparison.json)。

## 2. 核心结果

### 2.1 耗时

| 指标 | 本地 CPU 结果 |
| --- | ---: |
| Meyda 解码与分析中位数 | 334.77 ms |
| 新方案第一次冷请求 | 13,561.13 ms |
| 新方案模型加载后的中位数 | 651.20 ms |

新方案热运行约为 Meyda 的 1.9 倍，但仍低于一秒。真正影响体验的是 CLAP 首次加载，因此正式服务必须在启动阶段预热，不能让第一位用户承担模型加载时间。

### 2.2 CLAP 语义命中

| 语义组 | Top-1 命中 | Top-3 至少一项命中 |
| --- | ---: | ---: |
| 情绪 | 62.5% | 87.5% |
| 流派 | 37.5% | 62.5% |
| 乐器 | 25.0% | 62.5% |
| 质感 | 62.5% | 87.5% |
| 运动 | 75.0% | 100.0% |
| 空间 | 75.0% | 87.5% |

Top-3 只能说明正确候选有时存在于列表中，不能证明第一判断可靠。典型误判包括：

- Bach Cello Prelude 第一乐器候选为 `acoustic-guitar`，`cello` 排在第三。
- 《阳关三叠》的第一流派候选为 `baroque`，第一乐器候选为 `acoustic-guitar`。
- 《二泉映月》的情绪、流派和乐器均没有命中内部参考。
- Amœba 的电子、实验和环境流派全部进入 Top-3，但第一乐器候选为 `strings`。

### 2.3 调性与结构

在 4 首具有明确作品调性参考的样例中，新方案 key + mode 完全命中 2 首，命中率为 50%。它正确识别了贝多芬第五交响曲第一乐章的 C minor 和 Mozart Eine kleine Nachtmusik 的 G major，但未命中 Bach Cello Prelude 与 West End Blues。因此调性置信度也不能被理解为经过校准的正确概率。

Meyda 对所有 45 秒样例都按时长机械切成 `0-15 / 15-30 / 30-45` 三段。新方案根据 chroma、MFCC 和 onset 的变化峰生成不同边界，并附带边界置信度和段落阶段。即便这些边界仍需人工评估，它们已经比固定等分更接近“音乐结构证据”。

## 3. 对音乐家评论的影响

Meyda 的问题不只是字段少，还会把低层规则直接写成高层结论：

- 《阳关三叠》被描述为 191 BPM、“轻快、深沉、热烈”。
- 《二泉映月》被描述为“激昂、温暖、热烈”。
- 多数段落因动态阈值被统一描述为“爆发”。
- `visualMappingHints` 在用户和音乐家参与前就决定强光、形体张力和材质转场，不符合 Version 2 的共创架构。

新方案的优势在于保留 beats、onsets、动态曲线、数据分段、证据来源、分析器版本和不确定性。音乐家可以基于这些证据形成解释，而不是直接复述一个规则生成的 mood。

但 CLAP 仍会产生具体而错误的流派和乐器判断。若原样进入共享上下文，只会把旧的规则失真换成新的模型幻觉。

## 4. V2-03 决策

结论是“分层通过”，不是整包替换：

### 批准进入 V2-04

- librosa 的节拍、起音、动态和音色描述。
- 数据驱动的段落边界与段落变化。
- 每个字段的 evidence、analyzer version、confidence 和 warning。
- CLAP 的情绪、质感、运动和空间 Top-3，且只能作为低权重候选。

### 暂不作为事实

- CLAP 流派和乐器：Top-1 命中不足，上传音频不得直接使用。
- key / mode：保留为带置信度的分析假设，不写成确定乐理判断。
- 任何具体视觉意象：继续由音乐家、用户和 Visual Scribe 共同形成。

### V2-04 接入约束

1. 分析服务启动时预热 CLAP，消除 13 秒级首请求等待。
2. 预置和搜索音乐优先使用 catalog 中已知的流派、乐器与来源 metadata。
3. 用户上传音频不使用 CLAP 流派和乐器作为音乐家事实。
4. 情绪、质感、运动和空间只作为候选，并把分数与警告一同传递。
5. 服务失败时允许 Meyda 降级，但必须标记 `degraded`，不能伪装成同等质量结果。
6. Meyda 继续负责水晶和波形的实时动画，不再负责音乐语义结论。

在这些约束下，新方案对音乐证据的保留和可解释性明显优于现有 Meyda，可以进入 `V2-04` 正式接入。
